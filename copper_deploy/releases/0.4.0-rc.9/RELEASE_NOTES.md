# Copper 0.4.0-rc.9 内部安全修复与离线验收候选

`INTERNAL_REHEARSAL_ONLY`。本候选接续 rc.8 的真实安全扫描失败；rc.8 的冻结提交、三镜像构建输入及失败证据保持原样。rc.9 必须重新绑定三仓提交、真实镜像/导入 ID、当前漏洞库、六份 SBOM 和逐组件许可证原件。具体执行结果以本轮实际产物及 checkpoint 报告为准，不因源码修复提前宣称扫描或验收通过。

## 功能变化

MySQL 8.4.10 官方摘要基线保留；CA 信任库更新为 Oracle ELSA-2026-88459 公布的精确修复包，下载摘要与安装后版本均强制核对。删除 Copper 未使用的独立 mysql-shell RPM 及其内嵌 Python/certifi，保留 mysql、mysqldump、mysqlbinlog 和原有备份恢复入口。其他组件安全变更以实际冻结的 Web、Backend 提交为准；Critical 安全门槛保持原样，不补造例外或降低严重等级。

离线 Docker 依赖采用当前已认证官方 APT 的 Docker Engine/CLI 29.9.2、Compose 5.6.1、containerd 2.4.2 与 Buildx 0.38.1 精确版本和五个 DEB 摘要。介质桥接要求与本候选已审清单字节一致，显式路径也不能切回旧工具包；实际安装与二进制权利材料另据本轮证据记录。

沿用固定公网 IPv4 引导安装、自动 IP TLS、固定 ACME 客户端持久化、同版本 repair/continue 保留客户配置与备份公钥。不同公网 IP 或域名/IP 模式的 change-domain 在变更服务前停止，本候选不提供证书迁移事务。

## 数据库影响

以实际冻结 Backend 的 Flyway 清单计算目标 schema 和摘要；不修改历史迁移。rc.7 的 schema 68、92 外键及原生 MySQL 验证是既有基线，不能替代 rc.9 的真实容器备份恢复验证。

## 已知问题

授权验收主机为 Ubuntu 24.04 x86_64 的 18.142.134.26。安全修复必须在新构建中复验，再完成当前许可证台账、离线介质、真实 HTTPS、业务及附件、整站 full/incremental 加密备份、旁路验证、切换和重建后的业务连续性。每阶段单独记录实际状态。浏览器/手机与外部第三方步骤沿用产品负责人延期范围；这不是法律签字，也不替代许可证工程材料。已有 Docker 环境复用与 Copper 镜像离线导入分别记载，不宣称 Docker 离线安装已通过。

## 升级步骤

矩阵使用 `freshInstallOnly:true` 且直接升级来源为空。rc.8 失败输入及历史候选均不得作为本候选通过证据；本轮不承诺从旧候选直接升级。先完成隔离新站安装及恢复链路，再为未来来源逐项实测并增加矩阵。

## 停机与回退

数据库、附件和允许配置在同一停写边界备份。schema/data 变化通过已验证整站备份或保留旁路回退，不运行逆向 SQL 或旧镜像继续写入。主机不映射 Backend 8191，不操作用户正式服务。
