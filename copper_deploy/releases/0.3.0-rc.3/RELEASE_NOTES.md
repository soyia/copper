# Copper 0.3.0-rc.3 发布说明

> 渠道：内部验收 / 明确同意的试点 RC

## 候选顺延说明

- `0.3.0-rc.2` 完成 M4-03 供应链验收，但其 Backend 早于 M4-06 可信时间写保护，不作为 M4 最终候选发布。
- `0.3.0-rc.3` 绑定 GitHub Actions 生成的 Web、Backend amd64 工件及其源码提交、工作流编号、镜像摘要和离线归档校验值；离线交付工厂允许在无 GHCR Token 的可信工厂中验证并装入这两个 CI 工件。
- 本候选只有在 M4-07 真实 TLS、完全断网业务闭环、第三方降级、客户自助运维和故障复验全部通过后，才可创建不可变标签与 Release。

## 功能变化

- 客户回款只需选择出库单，Backend 会在同一事务内同步该出库单及其来源销售订单的已收金额与付款状态；只生成一条应收变动，避免“出库已付、销售应收仍未结清”或重复核销，并修复 MySQL 8.4 无符号关联编号读取导致的回款失败。
- Backend 在 root 控制的可信时间状态缺失、失效、过期或阻断时，拒绝资金、库存、订单状态、导出和权限等高风险写操作；销售退货同样纳入保护。
- 数据库、磁盘、备份介质、证书、时间异常和异常断电等价终止均已有失败关闭、恢复和经营财务不变量证据。
- 新增 `copperctl security egress status`，公开当前主动外联、第三方能力、遥测、许可证心跳和远程停用开关状态；状态输出不读取秘密内容或业务明细。
- 核心采购、入库、库存、销售、出库、收付款和查询不依赖 Copper 官方服务、公共互联网、强制遥测或远程许可证心跳。
- 域名证书续期、客户选择的 S3 备份、客户 Webhook 和管理员主动选择的联网交付是条件能力；失败必须明确降级，但不得阻塞无关核心业务。

## 正式离线交付

- 离线介质绑定部署归档、发布清单、升级矩阵、发布说明、ACME 客户端归档和三张 amd64 镜像的实际内容 ID。
- 客户服务器从离线介质导入镜像后，安装和运行不访问 GHCR 或 Copper 官方服务；已安装版本停止购买维护后仍可继续运行。
- 正式域名模式首次签发和续期证书需要访问公开 ACME 服务。取得有效证书后，短期断网不影响证书有效期内的 HTTPS 和核心业务；长期断网必须由客户在证书到期前恢复续期条件或改用受支持的客户 TLS 终止层。

## 数据库影响

- 数据库仍为 schema 5，迁移集合 V1 至 V5 与 `0.3.0-rc.2` 相同；本候选不新增表、不修改库存、应收应付、资金、核销、附件或审计数据结构。
- 从 `0.2.0-rc.1 / schema 4` 直接升级仍必须先创建加密整站备份，在保留旁路站执行 V5 和完整验证后人工切换。
- 当前 schema 声明的数据库外键数量仍为 0。应用级引用检查只能证明固定范围内没有孤儿，不能替代数据库约束；该结构风险不因 M4 完成而消失。

## 升级步骤

1. 从 `0.2.0-rc.1 / schema 4` 创建并离线验证新的加密整站备份。
2. 使用本候选发布清单执行升级预检和准备；来源版本、schema、恢复密钥、容量或健康不满足即停止。
3. 在保留旁路站执行 V5、完整经营财务和附件验证，人工确认后切换；不得手工执行写 SQL。
4. 无公共互联网时，使用正式离线交付介质导入三张绑定 amd64 镜像，禁止临时改用可变标签。

## 停机与回退

- schema 4 到 schema 5 属于维护窗口升级。切换前保持旧站旁路和已验证备份，失败时回到保留旧站或完整恢复备份。
- 禁止删除已经切换前的旧数据、逆向执行 SQL 或仅替换旧 Backend 镜像冒充回退。
- 全新安装不需要业务停机；域名 DNS、云安全组和首次 ACME 签发准备时间不计入应用安装耗时。

## 已知问题

- MySQL 8.4.10 官方镜像中的一次性降权工具 `gosu` 仍存在三项 Go 标准库 Critical 扫描结果；仅允许在最长 7 天、具名责任人与补偿控制的 RC 例外中继续验收，稳定发布继续阻断。
- 完全断网会使证书续期、S3 异地备份、Webhook 通知和联网升级不可用。客户应保留本地告警和离线发布介质，且不能把同机本地备份宣传为整机灾难保护。
- 本版本不承诺 7×24、零 RPO、即时恢复或无限人工服务；M7 仍需结合试点规模、实际人工成本和合同文本决定商业 SLA。
