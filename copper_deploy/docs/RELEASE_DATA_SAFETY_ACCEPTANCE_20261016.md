## 引用与构建合同

V67 起恢复验证要求 78 个指定核心外键映射及其立即限制删除/更新的语义；其余实际数据库外键继续全部生成孤儿校验 SQL。78 是核心保护集合大小，不是全库约束总数。V67 之前保留历史 schema 的恢复能力，不把尚未实际创建的补强约束强加给旧备份。

实际 V67 库复核发现，V57/V58 的 24 个既有映射由 MySQL 报告为默认 `NO ACTION`，新 V67 为显式 `RESTRICT`。已核对 [MySQL 8.4 官方外键文档](https://dev.mysql.com/doc/refman/8.4/en/create-table-foreign-keys.html)：InnoDB 的两种规则都立即阻止破坏引用的父删除或更新；NDB 的语义不同。因此没有改写历史迁移或伪改元数据，验证器仅在实际 `SELECT VERSION()` 为 MySQL 8.4 且相关父子表的真实 `information_schema.TABLES` 证据均为 InnoDB 时接受 `NO ACTION`。缺少引擎证据、其他版本/引擎、`CASCADE` 和 `SET NULL` 继续失败关闭。生产恢复入口会自动采集版本及引擎证明。

修复后在实际 MySQL 8.4.11 / V67 库重新交叉验证：78 个核心映射通过带引擎证明的规则检查，全库 92 个实际外键的 92 项孤儿查询全部为零，见 [真实库交叉结果](RELEASE_FK_CROSSCHECK_20261016.json)。

本地镜像构建可以使用摘要绑定的真实 `copper-local-build/v1` 证据，不再要求伪填 Actions Run。历史数字 Run 继续兼容。本地来源文件经过清单生成、交付索引、READY 落盘与篡改拒绝回归；预加载镜像还核对实际内容 ID、平台和源码提交。
