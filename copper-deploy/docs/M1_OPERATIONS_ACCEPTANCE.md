# M1-06 运维命令隔离验收记录

验收时间：2026-07-13。容器测试只在 `ec2-user@local-database` 执行，开发电脑未运行 Docker/Colima。测试站点使用外部代理模式，仅绑定 `127.0.0.1:18080`，未发布宿主机 8191/3306。

## 命令与配置

- `copperctl` 帮助、版本、未知命令和非法日志服务参数通过 CLI 契约测试；参数错误退出码为 2。
- 首次 `install` 创建配置模板后，因为安全路径/配置尚未完成以退出码 3 停止；填写隔离配置后重复执行完成安装，MySQL、Backend、Web 三层 healthy。
- `restart`、`down`、`up`、`status`、`logs` 和 `uninstall` 实际执行通过；`down`/`uninstall` 后配置、密钥、数据库、附件和备份保持不变。
- 数据库业务口令在 down/up 前后 SHA-256 一致，附件探针保持不变。

## Doctor 与管理员交付

- `doctor` 输出 20 项通过、3 项提醒、1 项失败。
- 唯一失败项是测试主机数据盘实际只剩约 4.1 GiB，低于 5 GiB 交付门槛；输出明确要求扩容或清理非 Copper 文件，并禁止直接删除 Copper 数据。
- 提醒项明确标识 ARM64 隔离测试不能替代正式 Ubuntu 24.04 amd64、外部代理 TLS 需要客户网络验证、首次管理员凭据待交付。
- `admin init` 只显示用户名、生成时间、受限文件路径和交付步骤，不输出密码；非交互终端执行 `--show` 被拒绝，避免凭据进入流水线或日志。

## 同版本停机备份与恢复

- `backup create` 按 Web → Backend → MySQL 顺序停止服务，生成 root:root 0600 的备份包和 SHA-256 校验文件，再自动恢复三层健康。
- 错误恢复确认文本返回失败，修改后的附件探针保持不变，证明没有进入破坏性阶段。
- 正确恢复确认先创建 `pre-restore` 安全备份；恢复后附件探针从修改值回到备份值，三层重新 healthy。
- 人为构造了配置损坏但外层/内层 SHA-256 均正确的备份包。恢复在配置门槛失败后自动回到恢复前域名、附件和数据，三层重新 healthy，并保留安全备份位置。
- 最后执行 `uninstall` 证明默认保留数据，再使用站点标识与精确二次确认永久删除隔离站点；测试目录、镜像、容器、网络和监听端口均已清理，只保留主机原有 `vm-mysql`、`vm-valkey`。

## 尚未替代的门槛

本记录证明 M1-06 命令和失败保护在 Linux ARM64 隔离环境有效，但不替代 M1-07 的全新 Ubuntu Server 24.04 LTS x86_64 端到端客户交付验收。
