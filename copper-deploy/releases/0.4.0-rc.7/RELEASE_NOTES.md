# Copper 0.4.0-rc.7 源码候选

本轮开发交付已完成。精确组合与校验值见 [源码冻结记录](SOURCE_FREEZE.json)；该记录绑定已验收的三仓源码，不冒充镜像发布清单。

## 行为变化

- 停用往来单位或对应身份后，待确认的库存和资金单据不能继续形成新事实；幂等重放、拒绝、作废和历史冲正仍可使用。正常编辑/确认及风控并发已补真实事务验证。
- 数量、实重包装及重量单位换算保持六位精度，小量库存不再显示为零或被两位输入截断；OCR kg 换算按受控重量单位处理。
- 备份和恢复核对十类原件，新增四类分别覆盖缺文件和同长度篡改拒绝；包装余量、领用及多商品成本按商品主键勾稽。
- V67 增加 54 条核心限制外键；V68 解决旧单与新明细的包装引用碰撞，并限制跨批次、跨商品包装冲正。既有迁移保持原样，脏数据失败关闭。
- 本地构建来源具有可校验合同，不再需要伪造 Actions Run；支持边界与版本生命周期已记录。

## 本轮证据

Web 175 项测试、类型检查和构建通过；Backend 227 项单元/契约和 103 项真实 MySQL 测试通过；Deploy 291 项 Python 回归及静态/版本合同通过。候选源码严格扫描为零命中。

真实提交的虚构经营数据经过实际加密导出与独立新库恢复：256 张表、3,999 条记录、2 个文件及引用完全一致，92 条外键零孤儿。使用 Java 17 与原生 MySQL 8.4.11；该恢复证据是原生补验，不冒充 Linux Compose 整站或正式 `copper-backup/v1` 包。
