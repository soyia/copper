# Copper 0.4.0-rc.1 M6 工程候选说明

> 渠道：内部 M6 权利与供应链证据验收；不是 Git tag、GitHub Release 或客户交付物。

## 功能变化

- 冻结当前 GitHub `main` 的 Web、Backend 和 Deploy 组合，重新生成与三仓精确提交和不可变镜像摘要一致的 M4 安全证据与 M6 权利证据。
- 权利台账同时覆盖六份 CycloneDX SBOM 中的直接/传递组件、基础镜像、构建/扫描工具、固定 GitHub Actions 动作、随发布包交付的 ACME 客户端和逐文件内容资产。
- 宏泰官网抓取快照和同步脚本不在当前 Web 源码树；历史可达性继续由 M6-02 的 GitHub 平台处置单独控制。
- MySQL 运行时保持官方 MySQL 8.4.10 基础镜像，仅以 Oracle Linux `util-linux/setpriv` 替换上游由 Go 1.24.6 构建的 `gosu`；M6-03 重新扫描该精确 amd64 镜像，Critical 漏洞必须为零。

## 数据库影响

- 数据库 schema 继续为 5，迁移集合 V1 至 V5 未改变；本候选不包含新的数据库迁移或业务数据转换。
- 该候选仍使用已实测的 `0.2.0-rc.1 / schema 4` 保留旁路升级合同；不得据此跳过升级前加密备份、隔离验证或人工切换。

## 升级步骤

1. 仅在受控的 Ubuntu 24.04 x86_64 发布工厂生成 `--candidate` 字节冻结包。
2. 以发布清单中的精确镜像摘要重新生成六份 SBOM、安全扫描和权利台账；任何未知依赖、未覆盖工具或内容资产均失败关闭。
3. 只有 M6-02 历史处置、M6-03 工程证据和 M6-05 法律复核都完成后，才可另行评估创建正式 tag、Release 或客户源码交付。

## 停机与回退

- 本候选只生成证据，不执行数据库迁移、业务切换、生产停机或客户环境写入。
- 任何未来 schema 变更继续使用保留旁路站或已验证整站备份恢复，禁止逆向 SQL 或仅替换旧镜像冒充回退。

## 已知问题

- M6-02 的 GitHub Support case #4575811 尚未清除平台托管的历史 PR refs；在严格扫描达到零前，源码交付与公开发布仍被阻断。
- M6-05 的知识产权律师复核仍为 `REQUIRED`。本工程候选不创建 Copper 最终 LICENSE、不开源承诺，也不作法律兼容性结论。
- MySQL 上游运行时依赖的 High 发现不会被删除或隐藏；RC 证据会记录它们及修复期限，任何稳定版仍按安全策略阻断未处置 High。
