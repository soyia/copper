# Copper 0.4.0-rc.5 M7-02 零支持安装复验候选说明

> `INTERNAL_REHEARSAL_ONLY`：本候选只用于 M7-02 第二份独立空白机安装、首次登录、数据保护、备份恢复和自由导演练，不是 Git tag、GitHub Release 或客户交付物。

## 本候选解决什么问题

- 精确绑定 2026-07-18 最新的 Web、Backend 与 Deploy `origin/main`，避免继续复用旧 rc.4 或旧安装器冒充最新闭集介质。
- 统一使用 Mac 一键安装入口、服务器维护菜单和 Mac 数据保护菜单；操作者不再手工拼装配置、复制镜像摘要或逐条执行安装命令。
- 保留断点续传、同版本继续、DNS 重新检测/换域名、可信 HTTPS 门槛、首次管理员一次性凭据销毁、客户持钥备份与隔离旁路恢复。
- 第二份样本开始计时后，Agent 不提供新增命令、不登录目标机、不代替操作者排障；手册不足即记录 `SUPPORT_REQUIRED`，不得把实时支持改写为零支持。

## 数据库与业务影响

- 目标 schema 仍为 7，迁移集合严格绑定 V1 至 V7；不新增、删除或重写迁移。
- Backend 精确复用已通过 M7-04 构建验证的当前 `main`；Web 重新从当前 `main` 构建，包含已合并的 M7-03 修复和后续路线图决策。
- 新安装样本必须验证铜排预设自动带出宽度与厚度、采购入库图片、销售出库、往来余额、完整导出和客户持钥恢复，不允许只验证登录页。

## 使用边界

- 只支持全新 Ubuntu Server 24.04 x86_64，最低 2 vCPU、4 GiB 内存和 20 GiB 可用磁盘。
- 本候选的正常入口不包含覆盖式安装、恢复出厂或永久删除；同版本修复必须保留客户数据和随机密钥。
- 若使用现有测试主机，必须先证明其已通过受控重建达到等价空白基线；仅删除 Copper 目录不等于全新操作系统。

## 正式发布阻塞

- GitHub 平台历史引用、发布权利与漏洞证据、外部专业复核、正式客户双人交接、异机无人值守备份/告警及既有实体延期项继续标记 `FORMAL_RELEASE_BLOCKED`。
- 本候选即使内部演练通过，也不得公开发布、创建 `v1.0.0` 标签、宣传为 Certified 或交付客户。
