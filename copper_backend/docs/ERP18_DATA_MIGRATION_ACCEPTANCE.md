# ERP-18 主数据与期初迁移内部验收

> 状态：`COMPLETED_CURRENT_INTERNAL_ERP_BASELINE`
>
> 日期：2026-07-23
>
> 边界：内部空白账套迁移和切换能力，不代表客户正式数据切换已经完成

## 1. 解决的经营问题

小微铜材经销商首次启用 Copper 时，需要把旧台账中的往来单位、仓库、商品、库存数量与成本、应收应付、预收预付、现金银行余额和总账期初一次性迁入。ERP-18 将它们放进同一批次，防止各模块分别导入后出现库存金额、往来余额、资金和总账互不相符。

本阶段不建设通用 ETL 平台，也不允许向已有正式经营事实的账套叠加期初。迁移只能使用七张固定业务工作表：

1. 往来单位；
2. 仓库；
3. 商品；
4. 库存期初；
5. 往来期初；
6. 资金期初；
7. 总账期初。

商品系列和科目体系必须先在 Copper 中建立。商品品类不写死，15 类铜材及后续新增品类均通过现有系列、规格字段和单位配置承载。

## 2. 状态和不可变规则

```text
PREFLIGHT_FAILED ──撤销──> ROLLED_BACK
PREFLIGHT_PASSED ──应用──> APPLIED ──确认切换──> CUTOVER
       │                         │
       └────────撤销─────────────┘
```

- 上传和预检只保存来源文件摘要、逐行规范化快照和错误，不形成库存、往来、资金或会计事实。
- 同一会计主体、期初日期和文件 SHA-256 只返回同一批次，不重复预检和应用。
- 应用必须在空白账套执行；已有库存批次或余额、已确认采购销售、往来源单、收付款、承兑、银行对账、发票或有效会计凭证时失败关闭。
- 应用逐行保存目标类型、目标主键和是否新建。库存形成批次、余额和不可覆盖的来源流水；应收应付形成可正常收付的来源单；预收预付形成账户流水；资金形成独立期初事实；总账形成草稿期初凭证。
- 已有往来单位、仓库、商品只能在唯一、启用且关键口径一致时复用。系统初始银行账户只有在未发生资金或对账业务时才能由迁移接管，撤销时精确恢复接管前快照。
- `APPLIED` 会自动执行完整勾稽但不记账。无后续出入库、收付款或其他记账事实时可整批撤销。
- `CUTOVER` 前再次勾稽，随后审核并记账期初凭证。切换后禁止整批无痕回滚，只能走业务调整、凭证冲销或越期调整。
- 已切换批次每天执行持续一致性检查；人工可随时重跑。检查结果和差异只追加、不覆盖。

## 3. 勾稽范围

一致性检查至少覆盖：

- 全部预检通过行都只应用一次，且往来单位、仓库、商品目标仍有效；
- 库存来源行、批次、库存流水、数量余额和成本金额一致；
- 期初应收、应付、客户预收、供应商预付的来源行、业务事实和账户流水一致；
- 资金来源行、资金期初事实、企业银行账户和 1001/1002 科目一致；
- 1405 库存商品、1122 应收、2202 应付、1123 预付、2203 预收和业务事实逐项一致；
- 期初凭证借贷平衡；确认切换后凭证行和总账分录完整对应。

系统勾稽不能替代企业会计对会计科目、纳税人身份、税务处理和法定期初数字的复核。

## 4. 权限和岗位

| 权限 | 默认岗位 | 作用 |
|---|---|---|
| `data.migration.view` | 老板、管理员、财务 | 查看批次、错误、勾稽和审计 |
| `data.migration.manage` | 老板、管理员、财务 | 下载模板、上传和预检 |
| `data.migration.apply` | 老板、管理员 | 将通过预检的批次应用为期初事实 |
| `data.migration.rollback` | 老板、管理员 | 在切换前且无下游事实时整批撤销 |
| `data.migration.cutover` | 老板、管理员 | 最终确认切换并记账期初凭证 |

财务可以准备和修正数据，但默认不能独立完成应用、撤销或最终切换，避免同一经办人无复核完成全部高风险步骤。只有一个人的小微商户仍需填写具体原因，并在切换前后分别保存检查结果。

## 5. 自动化与真实数据库证据

执行命令：

```bash
mvn -q test
COPPER_ERP18_DB_URL='jdbc:mysql://127.0.0.1:3318/copper_erp18?...' \
  COPPER_ERP18_DB_USERNAME=root \
  COPPER_ERP18_DB_PASSWORD='' \
  bash tests/run-erp18-data-migration-mysql.sh
```

2026-07-24 的隔离验收结果：

| 项目 | 结果 |
|---|---|
| 数据库 | 全新 MySQL 8.4 临时实例，V1-V55 共 54 个已发布迁移成功（V46 保留为空号） |
| 预检失败 | 借贷或业务勾稽差异逐行阻断，库存和凭证写入均为 0 |
| 幂等 | 同一期初日和相同文件 SHA-256 返回原批次；应用不重复写入 |
| 应用 | 七域形成可追溯目标，草稿期初凭证生成，全部一致性检查通过 |
| 撤销 | 切换前整批撤销库存、往来、资金及接管的银行账户，审计事件保留 |
| 切换 | 切换前后检查通过，期初凭证完成审核和记账，总账行数与凭证行数一致 |
| 切换后保护 | 整批撤销被明确拒绝 |
| 完整导出 | V55 六张迁移审计表全部进入 `copper-export/v1`，业务合计包含批次、资金和差异指标 |

验收脚本使用唯一临时 MySQL 数据目录和精确 PID 清理，不启动或停止正式 `8191` 服务。

## 6. 尚未替代的正式工作

- 客户真实旧系统数据仍需单独清洗、脱敏演练、负责人复核和正式切换计划。
- 正式切换必须使用客户确认的期初清单、备份、回退时限和企业会计签字口径。
- 迁移工具不自动取得或验证旧系统法定凭证、税务申报资料及银行回单真实性。
- 本验收不等于正式客户数据迁移、正式发布或灾难恢复交付。
