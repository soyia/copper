## 验收业务流

验收在独立、可回滚的会计主体和已结束期间内执行以下真实数据流：

`采购下单 -> 采购入库 -> 销售下单 -> 销售出库 -> 销售退货 -> 采购退货 -> 调拨出库/在途/调拨入库 -> 盘点盘亏 -> 成本调整 -> 供应商付款 -> 客户银行收款 -> 承兑收票/到期 -> 客户预收/退款 -> 进销项税票 -> 银行逐笔对账 -> 损益结转 -> 期末结账`

业务数字固定为可复算样例，不作为行业默认值：

| 事项 | 数量/金额 | 验收口径 |
| --- | ---: | --- |
| 采购入库 | 100kg × 11.30 = 1,130.00 | 库存与应付同时形成 |
| 销售出库 | 60kg × 22.60 = 1,356.00 | 成本 678.00，应收 1,356.00 |
| 销售退货 | 10kg / 226.00 | 恢复成本 113.00，冲减应收 226.00 |
| 采购退货 | 5kg / 56.50 | 冲减库存和应付 |
| 调拨 | 20kg / 226.00 | 发出在途、收货入库分别过账 |
| 盘点 | 目标仓 20kg 实盘 19kg | 盘亏 1kg / 11.30 |
| 成本调整 | 源仓 25kg，11.30 调至 12.00 | 调增库存金额 17.50 |
| 期末库存 | 44kg / 514.70 | 源仓 25kg / 300.00，目标仓 19kg / 214.70 |
| 销售结算 | 银行 800.00 + 承兑 330.00 | 退货后应收 1,130.00 全部结清 |
| 采购结算 | 银行 1,073.50 | 退货后应付全部结清 |
| 预收与退款 | 收 200.00、退 50.00 | 预收余额 150.00，不能伪造应收核销 |
| 进项发票 | 未税 950.00 + 税 123.50 | 货、应付、付款、会计税额四层勾稽 |
| 销项发票 | 未税 1,000.00 + 税 130.00 | 货、应收、银行/承兑、会计税额四层勾稽 |
| 银行期末 | 206.50 | 5 条流水逐笔匹配，流水余额连续且与总账一致 |

## 强制断言

- 15 个非承诺业务过账批次全部生成会计结果，不允许存在制证问题。
- 每张凭证逐张验证借贷相等，审核并记账后再核对总账借贷合计。
- 库存批次、仓库汇总、数量和成本金额同时核对，不能只验数量。
- 应收、应付分别按真实往来流水归零；客户预收独立保留 150.00。
- 进销项发票必须查验通过，并完成货、往来、资金、会计关系；进项用途必须确认。
- 银行 5 条流水全部匹配，无未匹配系统资金，调节表差额为零。
- 损益结转前，关账预览只能由 `PROFIT_CARRY_FORWARD` 阻断；结转记账后全部检查必须为 `PASS`。
- 最终调用正式 `FinancialCloseService.closePeriod`，确认期间状态和关账检查快照真实落库。
- 整场验收结束后回滚；会计主体、商品、往来单位、仓库和附件文件必须零残留。

## 为什么事务内显式生成凭证

生产环境在业务事务提交后调用 `AccountingGenerationCoordinator` 触发自动制证。验收为了在现有授权数据库上安全回滚，整场使用一个外层事务；外层事务不提交时，提交后回调不会执行。因此测试逐个调用同一生产实现 `AccountingService.generateForBusinessPosting`，不直接插入凭证、分录或总账。这个做法既验证正式映射和制证逻辑，也保持验收数据可完全回滚。

## 执行

只允许连接一次性或明确授权的验收数据库。脚本不内置账号和密码：

```bash
COPPER_ERP_E2E_DB_URL='jdbc:mysql://127.0.0.1:3306/<isolated_db>?useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true' \
COPPER_ERP_E2E_DB_USERNAME='<isolated_user>' \
COPPER_ERP_E2E_DB_PASSWORD='<isolated_password>' \
bash tests/run-erp-month-end-e2e-mysql.sh
```

成功标记：

```text
ERP_MONTH_END_E2E=PASS postings=15 vouchers>=19 tax_invoices=2 bank_lines=5 close=passed rollback=verified
```

GitHub Actions 使用独立的临时 MySQL 8.4 数据库执行同一脚本。PR 镜像验证以及 `main` 镜像构建必须依赖该作业成功。
