# Copper 商品主数据录入与导入 SOP

> 适用对象：老板、采购、销售、仓库和系统管理员
> 目标：让管、棒、板、带、线、排、电磁线、管件、阀门、磁材、焊材和组合件都能快速建档，同时保证库存、订单和历史追溯使用同一商品身份。

## 1. 先分清四类数据

| 数据 | 回答的问题 | 是否参与商品唯一身份 |
| --- | --- | --- |
| 商品身份 | 这批货能否与另一批货互换 | 是；由系列已发布的身份维度决定 |
| 供应商供货 | 哪家供应、供应商料号、起订量、交期和采购单位是什么 | 否；同一商品可有多个供应商版本 |
| 包装方案 | 一盘、一卷、一轴、一根或一箱怎样换算和追踪 | 否；包装与实重按版本保存 |
| 批次质量 | 本批炉号、卷号、质保书和实测结果是什么 | 否；只属于具体库存批次 |

禁止把供应商料号、网页名称、包装重量、价格、炉号或质保书编号拼进通用商品身份。否则同一种货会被重复建档，也无法跨供应商合并库存。

## 2. 单个商品快速建档

1. 在“商品中心”选择产品系列。系列决定身份字段、可选单位和初始包装规则。
2. 依次填写“基本信息、核心规格、单位与包装、来源与供应”四个分区。带星号且标记为“身份维度”的字段必须填写。
3. 牌号、材料状态、执行标准和单位必须从已启用主数据或别名中选择。找不到时提交为待处理配置，不要用相似值代替。
4. 查看重复预检。结果为“已存在”时进入已有商品；结果为“碰撞或不完整”时先处理冲突，禁止通过改 SKU 绕过。
5. 保存后检查系统生成的规格文本、库存主单位、采购/销售可选单位和包装来源版本。
6. 供应商料号、最小起订量、下单倍数、交期和供应商包装在“供应商供货”中维护；变更时发布新版本，不覆盖旧版本。

身份资料尚未规范化时，只能保存为“待复核”。待复核商品可以继续补资料，但后端会阻止它进入采购、销售、入库和出库；补齐规范值并通过重复检查后才能发布为可交易商品。

## 3. 矩阵批量建档

矩阵适合同一系列下变化多个规格维度的商品，例如不同外径与壁厚、不同宽度与厚度、不同线径与热级。

1. 先固定系列、牌号、材料状态、执行标准、库存单位和共同字段。
2. 选择一个或多个“逐行变化字段”，为每个字段填写候选值；系统先显示公共字段与各维度的组合数量和少量预览。
3. 单次最多生成或粘贴 200 行。超过上限时先减少候选值或拆批处理，系统不会在后台静默截断。
4. 确认生成后，系统逐行显示将创建的规格、SKU、重复结果和缺失字段；已有录入内容时必须确认后才会整体替换。
5. 只保留实际经营的组合。不要为填满矩阵创建不存在或不能采购的商品。
6. 一次提交前再次核对单位、包装和重复结果；部分冲突不能阻断其他安全行，但冲突行不得进入正式商品。

## 4. Excel / CSV 导入

### 4.1 预检

1. 下载系统当前模板，不沿用旧模板猜字段。
2. 原文件保持不变；上传后先完成列映射。
3. 系统保存文件摘要、模板版本、列映射、原始单元格和规范化结果。
4. 单次最多导入 5,000 行、256 列；单元格最多 10,000 个字符。CSV/XLSX 不接受公式或疑似公式内容，超限文件必须拆分或转为静态值后重新上传。
5. 每行只会得到六种结果：

| 建议 | 含义 | 默认处理 |
| --- | --- | --- |
| `CREATE` | 身份完整且系统不存在 | 可创建 |
| `CREATE_PENDING` | 基础字段可识别，但多端口、导体结构等结构化身份尚未补齐 | 只创建待复核商品，禁止进入业务单据 |
| `SAFE_UPDATE` | 身份相同，只更新允许变化的非身份字段 | 必须明确确认 |
| `SKIP` | 完全重复或主动忽略 | 不写正式数据 |
| `CONFLICT` | 未知别名、缺少身份字段、SKU/身份碰撞或目标已变化 | 阻断该行 |
| `INVALID` | 文件格式、字段类型或必填值不合法，尚未形成可比较的商品身份 | 修正源文件或映射后重新预检 |

### 4.2 冲突处理

- 未知单位、牌号、状态或标准：由管理员核实后新增别名或规范值，再重新预检。
- 同一身份对应多个现有商品：先在商品主数据中完成合并判断或停用处理，不能在导入页随意指定其中一个。
- SKU 相同但身份不同：修改错误来源数据；不能仅换一个自动 SKU 掩盖冲突。
- 文件内重复：保留一行，其余跳过。
- 已发布商品身份需要变化：先做身份规则碰撞预检并发布新版本；不得用安全更新直接改身份。

### 4.3 正式提交

1. 只有 `CREATE`、`CREATE_PENDING`、已明确确认的 `SAFE_UPDATE` 和有原因的 `SKIP` 可以提交；`CREATE_PENDING` 只建立待复核商品。
2. 提交逐行事务处理；某一行失败时保留其他行结果和失败原因。
3. 同一操作人以相同文件摘要、映射、模板版本和配置重复提交时返回原作业，不重复创建商品；不同操作人的作业相互隔离。
4. 提交后保存作业汇总、逐行结果、目标商品和字段血缘。禁止删除作业来隐藏错误。
5. 作业长期停在“提交中”时可点击“尝试恢复提交”。后端只在原执行租约超过保护时间后接管，已经成功或跳过的行不会重复执行；租约仍有效时只提示稍后重试。

## 5. 数量、单位与实重

- 库存数量统一使用六位十进制定点精度；界面不显示无意义的尾随零。
- `kg` 与 `t` 使用受控固定换算；件、只、套、根、支、盘、卷、轴、箱、包、桶等不能凭经验与重量互换。
- 标为“实际重量”的包装，在采购下单时可以使用参考重量估算；入库和出库必须录入或选择实际包装重量，实际重量才进入库存事实。
- 实重包装默认整包流转，不能自动拆包或复包。确需拆包时，应为该商品建立有依据的固定换算或按实际称重形成新包装记录。
- 采购单位、销售单位、库存单位和计价单位可以不同，但每次单据必须冻结换算来源、版本和计算结果。

单位名称、缩写和别名都由单位主数据统一维护。导入或供货档案遇到未知单位时，应先在“计量单位”中核实并增加别名；不得在商品、包装或订单页面临时创造自由文本单位。

## 6. 供应商报价怎样进入采购

1. 在商品主档选择供应商，维护供应商货号、采购单位、计价单位、含税口径、税率、报价、币种、最小起订量、下单倍数、交期、生效期和适用包装版本。
2. 每次修改发布新版本；过期版本只供历史追溯，不覆盖原采购单快照。
3. 采购选中供应商和商品后，系统显示当前有效报价、MOQ、倍数、交期和包装参考重量。数量不满足供货规则时先提示采购人员核实，不得悄悄忽略。
4. 实重包装的参考重量只用于订单预计数量。入库仍必须录入本批实际重量，预计值不能直接成为库存事实。
5. 报价、税率和包装版本必须随采购明细冻结；之后主档更新不改变已确认订单。

## 7. 来源资料与批次质量

- 来源资料按“资料头 + 不可变修订”保存 URL、文件名、摘要、内部版本、发布日期和内容快照；商品、供货档案、技术规格等只关联明确修订与页码。
- 来源关联先进入待复核，由有权限人员批准或驳回并填写意见；再次复核也保留历史记录。
- 当前功能登记资料元数据、URL 和摘要，不代表已经把外部附件上传到 ERP。需要长期留存的原文件应按企业文档与备份制度保管。
- 质保书、炉号、卷号、厂家批号和实测结果必须关联真实库存批次；商品技术规格保存目标，批次质量保存实际值，两者不能互相覆盖。

## 8. 已发布数据怎样改

- 商品身份规则、来源资料、供应商供货、包装、技术规格和 BOM 都通过新版本修改。
- 发布身份规则前必须预检现有商品碰撞与缺失；有碰撞时不得直接切换。
- 已确认订单、出入库、退货、库存流水和价格快照继续使用原版本，不因主数据更新而变化。
- 建错但尚无业务的商品可停用并注明原因；已经有业务历史的商品不得删除，后续使用正确商品并保留关联审计。
- 批次质保书和实测结果只追加、复核或作废，不得拿商品技术目标覆盖批次实测值。

## 9. 上线前验收清单

- [ ] 圆管、复杂内螺纹管、板、带、圆/方/六角/异形棒、线杆、绞线、铜排、电磁线、阀门、磁材、焊材和组合件各建一项。
- [ ] 每项都能完成快速建档、重复预检、采购、入库、库存查询、销售、出库和退货。
- [ ] 重量商品能使用 kg/t，实重盘卷能在入库与出库保留实际重量。
- [ ] 件数商品不能被随意换算成重量；未知单位和未知牌号会进入冲突。
- [ ] 同一商品可以维护两个供应商供货版本，库存仍归集到同一商品。
- [ ] 采购选择供应商后能看到当前报价、MOQ、倍数、交期和包装版本，订单冻结使用版本。
- [ ] 待复核商品不能进入采购、销售、入库和出库。
- [ ] 未知单位别名和未知牌号可由管理员在主数据入口处理后重新预检。
- [ ] 来源页码可以批准/驳回且保留复核历史；批次质保书不会写回商品技术目标。
- [ ] 历史单据在修改供应商、包装或技术规格后仍显示原快照。
- [ ] Excel/CSV 的创建、更新、跳过、冲突、重复提交和部分失败均有可追溯结果。
