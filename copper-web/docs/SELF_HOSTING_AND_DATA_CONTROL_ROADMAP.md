## 1. 使用和维护规则

GitHub 执行任务的拆分、依赖和待创建 Issue 定义见 `docs/GITHUB_ROADMAP_TASKS.md`。本文件仍是产品承诺和完成验收的权威来源；GitHub Project 用于日常指派和查看状态，不能反向降低本文件的退出条件。

### 1.1 状态说明

- `[ ]`：未完成。
- `[x]`：已完成，并且已经补充可复核的验收证据。
- `状态：进行中`：已有实现工作，但尚未满足里程碑退出条件。
- `状态：待验证`：代码或文档已完成，等待真实环境验收。
- `状态：阻塞`：必须同时记录阻塞原因、责任边界和解除条件。

### 1.2 勾选规则

- 不得因为“代码已写”“构建通过”或“本机可运行”就勾选完成。
- 每个完成项必须在本文件的“更新记录”中附上至少一种证据：代码路径、测试、安装记录、恢复记录、发布版本、合同/规则文档或真实环境验收结果。
- 跨前后端、数据库和部署脚本的事项，必须完成整条链路后才能勾选。
- 里程碑只有在全部必选项完成、退出条件通过、无未说明阻塞时，才能标记为完成。
- 如果目标或商业边界发生变化，先更新本文件，再开始实现，禁止让代码先形成事实标准。

## 2. 总体产品承诺

- [x] Copper 只有一套完整业务能力，不以基础版、专业版、旗舰版等方式切割功能。
- [x] 不按标准用户、仓库、商品、单据、历史年度收取软件功能费。
- [x] 不设置人为软件存储配额；实际容量由客户自己的磁盘、NAS、云盘或对象存储决定。
- [x] 产品方向覆盖客户本地设备、局域网服务器和客户自己的云服务器；实际可交付环境以完成真实验收的正式兼容清单为准。
- [x] 客户拥有服务器、数据库管理员凭据、备份文件和备份加密密钥。
- [x] 客户可以导出完整业务数据和可恢复的整站备份，不能只提供页面 Excel 导出。
- [x] 到期、停止维护或 Copper 停止经营时，不远程锁定客户已部署系统，不扣留客户数据。
- [x] 收入主要来自标准化部署、迁移、培训、维护、代运维和定制服务，不来自功能阉割。
- [x] 开放源码采用分阶段路线：先向客户交付可维护源码，再在发布准备完成后公开核心系统。

### 必须保持的严谨表述

- 对外使用“Copper 不设置人为存储配额”，不得使用脱离物理资源的“真正无限空间”。
- 对外使用“全功能无版本差异”，不得把服务响应等级、第三方资源成本描述成软件功能版本。
- 短信、OCR、电子发票、地图、云打印、对象存储等第三方费用，应单独说明实际提供方、计费主体和停用影响。
- 安全所需的单文件大小、类型、频率和并发限制，不属于收费配额，但必须可解释、可配置并保持各端一致。
