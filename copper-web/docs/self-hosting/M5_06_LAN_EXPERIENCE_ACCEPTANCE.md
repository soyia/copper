## 2. 已完成的工程实现

### 2.1 局域网状态与失败语义

- 顶部状态区区分“正在检测”“局域网主机可用”“浏览器离线”“Copper 主机不可达”和“连接已恢复”。
- 主机不可达时明确提示：主机可能关机、休眠或局域网地址变化，未收到成功提示的写操作均未确认成功。
- 浏览器离线时明确说明 Copper 不支持离线记账，避免把本地暂存或失败请求误认为已入账。
- 第三方外部功能异常与 Copper 主机不可达分开表达，外部功能只在对应页面降级。

### 2.2 未保存表单恢复

- 采购订单、销售订单、入库单和出库单按“当前用户 + 单据类型 + 新建/业务主键”隔离会话草稿。
- 意外刷新或短暂网络中断后可恢复未提交内容。
- 保存成功、明确关闭工作区页签、退出登录或会话失效后销毁草稿，防止旧内容在下一次新建单据时重新出现。
- 页面关闭前仍有未提交内容时使用浏览器原生离开提醒。

### 2.3 打印

- 采购订单和入库单使用统一 A4 打印版式。
- 销售订单和出库单保留 241 mm × 140 mm 针式连续纸版式。
- 统一处理打印标题、打印后清理、表头跨页重复和关键行避免分页断裂。
- 打印仍由浏览器与客户操作系统承担，不引入客户端打印插件。

### 2.4 扫码

- 入库页提供持续聚焦的 HID 键盘模拟扫码输入区，回车作为一次扫描结束符。
- 处理中文输入法组成态，组成文字未结束时不提前提交条码。
- 首次扫描创建明细；相同包装条码再次扫描时在原行累计数量，不创建重复行。
- 未识别条码显示明确错误并恢复焦点，可继续扫描下一件。

### 2.5 附件上传

- 首次保存入库草稿后复用同一 `inboundId` 上传附件，重试不会重复创建入库单。
- 每个文件独立记录等待、上传中、成功或失败状态；失败后保留表单和文件上下文。
- 支持只重试失败文件。
- 对“服务端可能已成功、客户端未收到响应”的不确定结果，以浏览器计算的 SHA-256 与服务端附件清单对账；已存在的同内容附件按成功处理。

## 3. Ubuntu x86_64 工程验收证据

隔离环境使用 Ubuntu 24.04 x86_64、Docker 29.1.3、Compose 5.1.4、MySQL 8.4.10 和独立 Copper Compose 项目。正式业务环境与开发者 Mac 均未被占用或重启。

### 3.1 初始化与安全

- MySQL 健康，Flyway V1 至 V5 完成，数据库为 90 张表。
- HTTPS 就绪检查通过；HTTP 跳转 HTTPS，MySQL 与 Backend 端口未直接映射到外部。
- 首次管理员一次性凭据完成改密后已销毁。
- 验收密码、Cookie、临时证书材料和测试数据只存在于隔离运行目录；验收结束后 Compose 项目、运行目录和本次 Web 测试镜像已整体销毁。

### 3.2 多会话、权限与审计

- 同一管理员建立 2 个独立客户端会话并发创建 2 个不同部门，两次写入均成功且业务主键不同。
- 验收时共观察到 5 个有效独立会话。
- 只读角色具有 `dashboard.view`、`purchase.view` 和 `inbound.view`，读取采购订单成功。
- 只读用户创建采购订单返回 HTTP 403，错误明确指出缺少 `purchase.manage`。
- 安全审计同时存在 `LOGIN_SUCCESS`、`CHANGE_PASSWORD`、`ACCESS_DENIED`、`CREATE_ROLE`、`CREATE_USER` 和两次 `CREATE_DEPARTMENT`。

### 3.3 浏览器、扫码、上传与恢复

- 真实 HTTPS 浏览器登录和工作台加载成功，顶部显示“局域网主机可用”，控制台无 warning/error。
- 采购订单写入未保存凭证说明后刷新，内容恢复；显式关闭工作区页签后再次新建，旧内容不再恢复。
- 包装条码首次扫描后加入正确商品；第二次扫描同条码后原行数量从 1 累加为 2。
- 同一附件首次上传成功；第二次上传返回 HTTP 400“已经上传”，服务端附件清单仍只有 1 条且 SHA-256 相同。
- 入库详情可查看已上传附件并显示“打印入库单”。
- 主动停止 Backend 后，页面显示“Copper 主机不可达”，未保存的两件扫码明细仍在；Backend 恢复后状态回到“局域网主机可用”，表单内容未丢失。
- 最终清理复核为：验收目录不存在、M5-06 容器为 0、本次 Web 测试镜像不存在、80/443 端口无遗留监听。
