# 部署与运行责任矩阵

> 状态：内部产品与交付规则
> 对应任务：GitHub `soyia/copper_web#2`
> 适用模式：自助部署、标准部署、代运维

> M7-06 首发范围：`1.0` 标准部署只规划客户自有公网云 Ubuntu Server 24.04 LTS x86_64。本地/LAN、Windows 宿主 VM、NAS、ARM64 和 macOS 不属于首发标准环境；代运维在异机通知样本完成前也不形成可售服务。

## 1. 不变原则

- 服务器或云账号原则上由客户实名购买并持有。
- 域名、证书账号、数据库管理员凭据、备份文件和备份加密密钥必须交付客户。
- Copper 人员只获得完成已授权服务所需的最小权限，服务结束后应撤销临时权限。
- 删除数据、覆盖恢复、开放公网端口、修改安全策略和不可逆升级必须取得客户明确确认。
- 停止服务后，Copper 不远程停机、不锁定软件、不扣留数据。

## 2. 模式定义

| 模式 | Copper提供 | 客户承担 |
| --- | --- | --- |
| 自助部署 | 软件、发布包、公开文档和社区信息 | 全部安装、配置、安全、备份、恢复、升级和日常运维 |
| 标准部署 | 在首发兼容的客户云环境完成一次标准安装、初始化、备份配置、恢复验证和交接 | 持有云账号、域名、DNS、备份和恢复密钥；交接后负责日常监控、备份保管、安全和升级决策 |
| 代运维 | 按合同执行监控、备份巡检、升级协助和故障处置 | 持有基础设施和最终控制权，审批危险操作，承担业务数据和第三方账号管理责任 |

## 4. 第三方服务边界

| 第三方能力 | 责任规则 |
| --- | --- |
| 云服务器、对象存储、CDN | 客户直接购买并接受供应商条款；Copper不承诺第三方可用性 |
| 短信、OCR、地图、物流 | 客户授权账号和额度；费用、识别准确性和覆盖范围由提供方决定 |
| 电子发票、税控、银行接口 | 必须由客户会计、税务或资金负责人确认开通和业务口径；Copper只按明确接口处理 |
| 云打印和硬件驱动 | 受打印机、操作系统、驱动和网络影响；正式支持型号进入兼容清单 |
| 域名和证书 | 客户持有域名；免费证书、商业证书的签发和续期条件由证书机构决定 |

## 5. 权限和高风险操作

以下动作不得用“已购买代运维”概括授权，执行时必须单独确认目标、影响和恢复方式：

- 删除数据库、数据卷、备份或附件。
- 用备份覆盖现有生产数据。
- 放开数据库、管理后台或远程桌面公网访问。
- 修改域名、证书、DNS、网络安全组或防火墙。
- 执行包含数据库结构变化的正式升级。
- 查看或导出超出故障处理所需范围的客户业务数据。

## 6. 故障归因原则

- Copper 产品缺陷：Copper负责提供修复方案或修复版本；是否立即升级由客户决定。
- 客户环境或操作：客户承担修复和数据恢复责任，Copper可按服务目录提供协助。
- 第三方故障：由客户向第三方主张服务，Copper协助提供必要日志和影响判断。
- 无法明确归因：先保护现场、停止危险写入并恢复业务，再依据日志和审计记录确认责任。

## 7. 交付证据

每次标准部署或代运维交接至少记录：

- 服务器和域名归属。
- 当前软件和数据库版本。
- 数据、附件和备份路径。
- 最后一次成功备份及恢复验证结果。
- 客户已取得的管理员账号和密钥。
- Copper仍持有的临时权限及撤销时间。
- 已知风险、未完成事项和责任人。
