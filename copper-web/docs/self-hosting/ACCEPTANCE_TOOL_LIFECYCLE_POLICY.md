# Copper 开发与验收工具生命周期规范

> 状态：立即生效
>
> 适用范围：M1 至 M7 的内部演练、真实设备验收、私有化部署验收和正式发布前复核
>
> 产品运行边界：Copper 正式运行时不依赖无界面浏览器、Playwright、Puppeteer 或开发者辅助进程

## 1. 目的

开发与验收工具必须像正式产品一样具备完整生命周期。工具完成任务、失败、超时、被中断或调用会话退出后，都不得把浏览器、Helper、Crashpad、监听端口、容器、临时配置、测试秘密或其他后台资源留在客户、操作者或开发者主机上。

如果一次验收结束后仍需要普通用户打开活动监视器、重启电脑、执行终端命令或求助 AI 才能恢复日常软件，该次验收工具即判定失败。业务页面或打印结果正确，不能抵消工具清场失败。

## 2. 2026-07-17 问题记录

2026-07-16 的 M5-06 打印版式开发验收曾直接调用开发者 Mac 上的日常 Google Chrome，通过多组 `--headless`、`--print-to-pdf` 和独立 `--user-data-dir=/tmp/copper-*` 生成 PDF。六份 PDF 均在数秒内成功生成，但六个 Chrome 主进程、十八个 Helper 和六个 Crashpad 未随调用会话退出；Chrome 升级后，旧进程继续存活并影响日常 Chrome 启动。

现有前端打印仍使用浏览器原生 `window.print()`，后端也没有启动 Chrome/Chromium 的业务代码，因此该事件不是 Copper 客户运行时缺陷，也不推翻 M5-06 的实体打印结果。缺陷属于开发验收工具缺少“拥有、等待、超时、异常退出和最终清场”闭环，必须纳入后续私有化部署和 M7 验收门槛。

## 3. 强制隔离规则

1. 每次运行必须生成唯一 `run_id`，所有临时目录、日志、浏览器配置、输出和进程标识都必须能够回溯到该 `run_id`。
2. 自动化浏览器优先使用专用 Chrome for Testing 或工具自带的隔离 Chromium；禁止直接调用操作者日常使用的 Chrome、Edge 或其默认用户配置。
3. 浏览器配置必须位于本次运行专属目录，禁止使用或修改客户/操作者的默认浏览器 Profile、账号、Cookie、扩展、书签和历史记录。
4. 启动方必须保存自己创建的根进程和子进程关系。禁止使用不带本次运行标识的 `killall`、全局 `pkill` 或按程序名称批量结束进程，避免误伤用户自己的软件。
5. 验收工具不得要求关闭用户已经打开的正常浏览器、数据库、正式 `8191` 服务或其他不属于本次运行的资源。

## 4. 强制收尾规则

1. 正常完成、命令失败、整体超时、`INT`、`TERM`、`HUP` 和调用会话退出必须进入同一最终清理流程。
2. 输出文件已经存在不等于进程已经退出。启动方必须等待并回收根进程；超时后先对本次运行拥有的进程执行正常终止，再在限定时间后强制结束仍存活的本次进程。
3. 清理必须覆盖本次运行创建的浏览器主进程、Helper、Crashpad、监听端口、容器、网络、卷、临时 Profile、一次性秘密和非保留临时文件。
4. 需要保留的日志和证据必须先写入明确的证据目录并生成清单；不得以“保留证据”为由留下运行进程、秘密或整套浏览器 Profile。
5. 清理逻辑本身失败时，工具必须返回失败并输出本次 `run_id`、已知资源和安全恢复说明，禁止报告验收成功。

## 5. 浏览器验收专项规则

- Copper 产品打印只验证 `window.print()`、打印预览和实体打印结果，不为客户安装或启动额外无界面浏览器。
- 自动截图、DOM 取证或 PDF 比对需要无界面浏览器时，必须使用专用测试浏览器并由支持生命周期清理的统一入口启动。
- `--headless` 只表示没有窗口，不代表进程会自动成为临时进程；`--print-to-pdf` 成功也不能代替进程退出检查。
- 在没有专用测试浏览器或可靠清理入口时，该自动化步骤应标记为阻塞或改用人工浏览器验收，不得临时调用用户日常 Chrome 冒险完成。

## 6. 前后基线与零残留验收

每次真实环境验收必须在开始前和结束后分别采集同一范围的基线，至少包括：

- 本次可能使用的进程及其启动参数；
- 本次可能占用的监听端口；
- 容器、镜像、网络、卷和 Compose 项目；
- 临时目录、浏览器 Profile、测试秘密和证据目录；
- 正式业务服务的身份、端口和健康状态。

退出条件固定为：

- 本次新增的非证据进程、监听、容器、网络、卷、临时 Profile 和秘密均为 `0`；
- 开始前存在且不属于本次运行的资源身份和状态不变；
- 操作者日常 Chrome/Edge、正式 `8191` 和其他业务环境未被停止、替换或要求重启；
- 证据清单记录 `run_id`、工具版本、开始/结束时间、根进程、退出状态、清理状态、前后差异和异常处置。

任一项不满足时，业务验证结果可以保留为局部证据，但整次验收不得标记为完成。

## 7. M7-02 及后续执行要求

M7-02 开始前必须先清理并复核本次已发现的历史无界面 Chrome 残留，再建立操作者主机的初始基线。M7-02 至 M7-07 的每份样本都必须包含开发/验收工具清场结果；任何额外 Agent 或研发工具产生的资源同时计入支持事件和清理清单。

客户交付包只能包含客户真正需要的正式工具。开发截图、临时代理、浏览器自动化、调试端口和证据采集辅助工具不得随交付包常驻客户环境，也不得把清理责任转嫁给客户。
