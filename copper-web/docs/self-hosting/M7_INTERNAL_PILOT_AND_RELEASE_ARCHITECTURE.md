# M7 内部试点、价格验证与正式发布决策架构

> 状态：M7-01 架构已冻结；M7-06 已完成 1.0 首发环境范围决策
>
> 总跟踪：[`soyia/copper_web#72`](https://github.com/soyia/copper_web/issues/72)
>
> 当前授权范围：`INTERNAL_REHEARSAL_ONLY`
>
> 正式对外状态：`FORMAL_RELEASE_BLOCKED`

## 1. 目的

M7 不再以“代码能运行”作为主要问题，而要回答四个经营问题：普通经营者能否在不依赖研发人员的情况下完成安装和日常业务；客户能否自己掌握升级、备份、恢复、导出和密钥；当前低价服务是否覆盖真实人工与风险；现有证据是否足以支持 `1.0.0`、正式收费交付或公开发布。

本架构把内部演练、真实试点、正式收费交付和公开发布分开。产品负责人此前要求先走完整流程、看到结果，因此 M7-02 至 M7-06 可以在正式门槛未清零时进行内部演练；所有缺口继续以 `FORMAL_RELEASE_BLOCKED` 跟踪，不得用内部成功替代正式证据。

## 2. 四种状态

| 状态 | 允许的参与者和数据 | 允许的动作 | 禁止的结论 |
| --- | --- | --- | --- |
| 内部演练 | 产品负责人、内部观察者；仅虚构数据和一次性秘密 | 打包、安装、经营、升级、恢复、报价和单据演练 | 不得称客户试点、正式交付、正式报价或已开源 |
| 真实试点 | 已书面知情的低风险试点主体；只处理约定范围的数据 | 按试点协议部署、迁移、培训、支持和验收 | 不得把一个试点外推成所有环境和所有客户 |
| 正式收费交付 | M0-M7 正式门槛通过，订单、责任和数据授权有效 | 按正式价格、兼容清单和服务范围交付 | 不得口头扩大服务、环境、RPO/RTO 或功能承诺 |
| 公开发布 | 权利、安全、许可证、源码和发布门槛全部通过 | 创建正式公开仓库、稳定版 Release 和公开材料 | 不得包含客户数据、秘密、受限资产或未决许可证 |

任何文档和证据只能标记自己实际达到的状态。内部演练包必须带 `INTERNAL_REHEARSAL_ONLY`，并同时列出正式阻断项。

## 3. 固定原则

1. Copper 始终是一套完整业务能力，不按用户、仓库、单据、历史年度或人工存储配额拆版本。
2. 低价依靠标准环境、自动化和明确服务额度，不依靠删除库存、往来、资金、备份恢复或源码自主能力。
3. 自助部署必须由目标操作者亲自执行。Agent 或研发人员直接登录主机、补命令、写 SQL、改源码或绕过工具，均不能记为“零干预成功”。
4. 首次失败是有效样本，必须保留原因和恢复成本；禁止反复排练后只记录最后一次成功时间。
5. 研发基线建设、客户环境等待、标准交付人工和售后风险分开核算，不能互相转嫁来证明低价合理。
6. M5 延期项和 M6 正式阻断继续独立存在。M7 内部演练不会产生本地平台 `Certified`、正式源码交付或公开开源结论。
7. `1.0.0` 只在 M7-07 明确 `GO` 后创建；内部演练和 RC 不得提前占用该版本。
8. 开发与验收工具必须遵守 `ACCEPTANCE_TOOL_LIFECYCLE_POLICY.md`。工具残留、误伤操作者日常软件或需要用户额外清场，均属于验收失败，不能用业务结果正确抵消。
9. M7-06 采用证据驱动的首发范围：`1.0` 只纳入客户自有公网云上的 Ubuntu Server 24.04 LTS x86_64；本地/LAN、Windows 宿主虚拟机、NAS、ARM64 和 macOS 不因方向正确或镜像可构建而进入首发兼容清单。

## 5. M7-02 操作者主导演练

### 5.1 角色

- **操作者**：产品负责人，模拟无源码开发经验的小微经营者，亲自运行文档命令和浏览器流程。
- **观察者**：Agent 解释术语、计时、记录问题和核对结果，默认不 SSH 登录、不代为复制命令、不修改服务器。
- **研发介入**：只有发现发布包、文档或产品阻断时才发生；一旦介入，本次样本标记为“需要支持”，修复后重新开始下一份独立样本，不能继续宣称零干预。

### 5.2 支持事件分类

每次超出正式手册的信息都必须编号：

| 分类 | 例子 | 责任处理 |
| --- | --- | --- |
| 文档缺陷 | 步骤缺失、命令错误、参数含糊、没有恢复路径 | 修正文档并重新从受影响步骤验证 |
| 产品/自动化缺陷 | 安装脚本失败、错误提示无效、状态与事实不符 | 建 Issue、修复、回归；不得人工绕过后记成功 |
| 环境前提 | DNS 未生效、云防火墙未开、磁盘不足 | 纳入预检或客户责任清单 |
| 操作理解 | 术语不清、按钮难找、错误后不知道下一步 | 改交互/培训材料或明确必要培训 |
| 第三方等待 | 域名、证书、云厂商、网络限制 | 单独记录等待时间和收费边界 |

Agent 直接执行一次主机命令记为一次“直接支持”；一次会话中连续修复同一根因可以归为同一事件，但必须记录主动人工分钟。

### 5.3 硬门槛

- 不写 SQL、不修改源码、不暴露 MySQL/Backend 到公网、不使用公共默认密码。
- 不读取或交给 Copper 保存恢复私钥；客户持钥证据必须真实。
- 安装、首次改密、备份、恢复、导出和卸载/保留数据都必须走正式工具。
- 失败后保留输入、原站和可恢复数据；不得删除当前可用站点来掩盖恢复失败。
- 每个成功结论必须有命令状态、浏览器结果、摘要、清单或交接单据支持。
- 额外 Agent/研发工具只能使用专用运行环境和唯一 `run_id`；不得调用操作者日常 Chrome/Edge 或默认 Profile。
- 样本开始前和结束后必须核对同一宿主范围，本次新增非证据进程、监听、容器、网络、卷、临时 Profile 和秘密均为 `0`，既有资源身份和状态不变。
- 若操作者需要活动监视器、重启、额外终端命令或 AI 才能恢复日常环境，本次不得记为“零研发干预成功”，必须登记支持事件并以新样本重验。

## 6. 必测业务和运维链

### 6.1 首日经营链

M7-03 至少完成：经营主体和用户权限；客户/供应商共用往来单位；联系人和地址；代表性商品、SKU、规格和单位；采购订单、入库、库存、销售订单、出库、应付、应收、付款、收款、核销和对账；附件、A4 打印、手机受限账号、完整导出和审计追溯。

十五类商品的可配置性必须由自动契约覆盖，人工样本应选择重量、长度、件/支/盘等不同计量形态，不能只用一种普通圆管假装完整适配。

### 6.2 生命周期链

M7-04 至少完成：受支持来源升级；升级失败恢复；计划和手工加密备份；离线私钥解密校验；旁路恢复；独立替换环境换机恢复；完整人可读导出；阻断公共互联网后的核心经营；最终回滚或清场。

云端替换环境只能证明云端换机。真实外接盘、远程 NAS、独立本地设备 B、Windows 宿主 Ubuntu VM、扫码枪和针式打印等 M5 延期项仍按原 Issue 验收。

## 7. 指标与证据

### 7.1 每份样本必须记录

- 环境：云厂商/虚拟化方式、OS、架构、CPU、内存、磁盘、网络、域名与证书前提。
- 版本：三仓提交、迁移集合、镜像摘要、安装包和文档提交。
- 时间：总墙钟、操作者主动时间、自动等待、第三方等待、Agent/研发支持时间。
- 质量：尝试次数、支持事件、失败步骤、根因、是否可从提示独立恢复、是否需要重新开始。
- 经营：完成的单据和状态、库存/往来/资金核对、附件、导出和审计结果。
- 运维：安装占用、经营数据增量、备份大小/时间、恢复时间、停机时间、失败恢复，以及按 `run_id` 记录的进程/监听/容器/临时目录前后差异和清理结果。
- 学习：首次完成时间、需要查找的位置、误解术语、培训问题、手机/桌面差异。

第一份内部样本用于建立基线，时间指标以观察为主，不为了满足任意分钟数删除步骤。M7-05 在多份无研发介入样本后才能冻结正式服务工时和价格阈值。

### 7.2 正式样本最低要求

M7-01 最初要求在 M7-07 前取得客户云、本地/LAN 和第三环境三类样本。M7-06 复核后，现有本地/LAN 与第三环境均缺少精确真实设备的完整链路证据，因此已全部移出 `1.0` 首发兼容清单，不再用未取得的三环境样本阻断彼此独立的客户云首发演练。

`1.0` 正式 M7-07 前的最低环境证据改为：

- 至少一个客户自有公网云 Ubuntu Server 24.04 LTS x86_64 完整样本；
- 至少一个使用精确 `origin/main` 闭集介质、由非研发操作者完成且没有新增支持命令的第二样本；
- 每增加一种拟对外支持的云平台、虚拟化方式、本地主机、NAS 或 CPU 架构，都必须先补齐该精确组合的安装、经营、升级、备份、离线验证、恢复、重启、导出和清场证据。

AWS 新加坡样本只能证明该精确 AWS 形态。其他云厂商即使满足相同资源合同，也先保持 `Candidate`，不得宣传为“所有云服务器普遍支持”。完整范围决定见 `copper_deploy/docs/M7_06_MULTI_ENVIRONMENT_SCOPE_DECISION.md`。

## 8. 价格和服务成本

M7-05 按以下口径逐样本核算：

`标准交付成本 = 标准人工时间成本 + 实际基础设施/第三方成本 + 税费及支付成本 + 预期售后成本 + 退款与安全风险准备`

研发修复时间单独列为产品成本；客户未满足前提产生的等待和非标准处理单独列为客户责任或额外服务。两者都不能悄悄塞进标准部署工时。

必须复核当前内部目标价：自助部署 ¥0；客户云部署 ¥349；本地/NAS 部署 ¥649 起；安心维护 ¥349/年；代运维 ¥99/月或 ¥995/年；标准迁移 ¥249 起；非标准服务和定制 ¥150/小时。结论只能是保持、调整或暂不发布，并附样本、公式、服务额度和生效范围。若价格不成立，调整价格、响应窗口或服务内容；不得制造功能阉割版。
