# 客户源码交付与公开开源策略

> 状态：长期开放源码策略；中国境内试运营客户源码使用按 `CHINA_TRIAL_TERMS.md` 执行
> 对应任务：GitHub `soyia/copper_web#4`
> 强制门槛：正式公开仓库、接受外部贡献，或签署公共SaaS、OEM、跨境及其他超出中国低风险试运营范围的源码商业授权前，必须完成知识产权律师、第三方许可证和提交历史审计；境内低风险试运营按 `CHINA_TRIAL_TERMS.md` 执行。

## 1. 目标

- 客户不因 Copper 停止服务而失去运行、修复和迁移能力。
- Copper 核心业务能力最终可以公开审查、构建和部署。
- 商业收入来自交付、运维、专业支持、定制和品牌信任，而不是数据锁定。
- 在开放源码的同时，用著作权、强网络 copyleft、商标和商业授权管理 OEM 与闭源再发行。

## 2. 分阶段策略

### 阶段A：公开开源前的客户源码交付

正式部署客户应取得与其运行版本一致的源码交付包，至少包括：

- `copper-web` 前端源码及锁定依赖。
- `copper_backend` 后端源码及构建配置。
- 数据库 schema、从该客户起始版本到当前版本的全部迁移。
- 正式部署、备份、恢复和升级脚本。
- 构建说明、版本标签、发布包校验值和第三方依赖清单。

客户源码授权草案应赋予客户：

- 永久内部运行、备份和灾难恢复权利。
- 为自身业务修改、构建和部署的权利。
- 委托受保密义务约束的服务商维护自身部署的权利。
- 不受用户数、仓库数、商品数、单据数和人工存储配额限制。

在公开开源前，客户源码授权草案不当然赋予：

- 向无关第三方公开源码或安装包的权利。
- 改名后销售、出租、提供公共SaaS或作为OEM产品分发的权利。
- 使用 Copper 名称、Logo、域名或“官方认证”标识的权利。
- 要求 Copper 无偿维护客户自行修改代码的权利。

以上限制已在 `CHINA_TRIAL_TERMS.md` 中形成中国境内试运营条款；公共SaaS、OEM、跨境或高金额授权仍需专项合同。

### 阶段B：核心系统公开开源

完成 M6 门槛后，建议将完整核心系统采用 AGPLv3 公开，并保留商业双授权：

- GitHub `origin/main` 为唯一权威源仓库。当前 M6 工作不访问或同步 Gitee；未来增加任何镜像必须另行批准为只读单向镜像，并以 GitHub 的代码、标签、Release 和校验值为准。
- AGPL版本允许使用、修改和再分发；通过网络向用户提供修改版本时，应按许可证要求向这些用户提供对应源码。
- 需要闭源嵌入、OEM、不给网络用户提供修改源码或使用商业品牌支持的主体，可申请商业授权。
- 公开开源不等于放弃 Copper 商标、官方签名、认证服务和商业支持。

真正的开源许可证允许商业使用和再分发，因此不得宣传“开源但禁止任何人收费”。商业保护必须依靠许可证义务、商标、官方发布供应链和服务质量。

## 3. 公开范围

正式公开核心应包括：

- 完整前后端核心业务源码。
- 数据库初始化和不可变迁移历史。
- 可复现的构建、部署、备份、恢复和离线升级资产。
- 安全报告入口、贡献指南、依赖许可证和软件物料清单。

可以保留为 Copper 内部服务资产的内容：

- 厂商内部工单、客户服务排班、服务计费和内部运营系统。
- 官方签名密钥、发布基础设施凭据和安全响应内部资料。
- 特定客户受保密义务约束的数据、迁移规则和定制代码，具体按客户合同处理。

不得以“内部服务资产”为名，把采购、库存、销售、应收应付、收付款、备份恢复等核心能力做成闭源高级版。

## 4. 第三方与内容版权

公开前必须逐项审计：

- Java、JavaScript、字体、图标、图片和构建工具许可证。
- 商品目录、网站采集文本、图片、标准文件和示例数据的再发布权。
- 提交历史中是否存在客户数据、密钥、数据库备份或无权再许可代码。
- 外部贡献者是否同意使 Copper 继续具备 AGPL与商业双授权权利。

第三方组件继续适用其原许可证，Copper 客户源码授权不能覆盖或改变第三方权利。

## 5. 客户修改和支持边界

- 客户可以自行修改，但应保留原版本、修改记录和数据库迁移记录。
- 客户修改导致的数据错误、安全问题或升级冲突，不自动属于 Copper 标准维护责任。
- Copper 在接管修改版本前可以要求代码审查、测试、备份和风险评估，并按实际服务计费。
- 无论是否修改，客户都应能先导出完整数据并恢复到可验证备份。

## 6. M6/M7专项复核清单

- [ ] 客户源码授权的使用、修改、委托维护、转售、SaaS和OEM边界。
- [ ] AGPLv3 与商业双授权是否适合当前依赖和商业模式。
- [ ] 外部贡献采用 CLA、版权转让还是其他授权方式。
- [ ] Copper名称、Logo、域名和官方认证商标规则。
- [ ] 既有客户从私有源码授权切换到公开许可证的衔接方式。
- [ ] 无担保、责任限制、安全更新和第三方组件条款。

专项复核完成前：

- 不创建最终 `LICENSE` 文件。
- 不将仓库设为公开并宣称正式开源。
- 中国境内低风险试运营使用 `CHINA_TRIAL_TERMS.md`；超出其适用范围时不得直接套用。
