# 15 类铜品类逐类可用验收

> 本文是商品范围基线的可执行验收说明。只有迁移成功、自动化业务链通过且事务回滚验证通过，才能声明“15 类均可用”。页面出现分类或能保存商品，不等于业务可用。

## 验收口径

每一类商品必须独立完成以下链路，不能共用另一品类的商品或库存冒充通过：

`商品建档 -> 必填规格/SKU 签名 -> 采购订单确认 -> 采购入库审核 -> 库存批次查询 -> 销售订单确认 -> 销售出库 -> 销售退货 -> 采购退货 -> 客户收款与来源核销 -> 供应商付款与来源核销 -> 库存及应收应付结存复核`

数量口径统一使用：采购及入库 `10`、销售及出库 `2`、销售退货 `1`、采购退货 `1`，最终批次与库存汇总结存均应为 `8`。每类以采购单价 `50`、销售单价 `80` 验证退货后应付 `450`、应收 `80`，分别完成付款、收款与来源核销后余额归零。六类来源单据必须产生稳定业务过账结果，验收数据必须在事务结束后完全回滚。

## 执行

使用专用 MySQL 验收库执行，禁止把验收数据写入生产库：

```bash
COPPER_15_CATEGORY_DB_URL='jdbc:mysql://127.0.0.1:3306/<isolated_db>?useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true' \
COPPER_15_CATEGORY_DB_USERNAME='<isolated_user>' \
COPPER_15_CATEGORY_DB_PASSWORD='<isolated_password>' \
tests/run-15-product-category-mysql.sh
```

成功标志：

```text
FIFTEEN_PRODUCT_CATEGORY_ACCEPTANCE=PASS families=15 packaging=5 rollback=verified
```

验收脚本会执行 Flyway，因此目标库必须是一次性或明确授权的验收库。测试本身运行在事务内，并在事务结束后复核商品、往来单位和仓库夹具均已回滚。

## 发布验收

个人开发默认以本地测试和专用真实 MySQL 验收作为证据，保存实际运行结果及回滚复核，不触发或等待 GitHub Actions。提交包含 `[skip ci]`。只有产品负责人明确启用 Actions 时，才使用 `.github/workflows/publish-m1-image.yml` 中的独立 MySQL 任务及镜像依赖门禁。
